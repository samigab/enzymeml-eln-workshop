# A pip-installable equivalent of the project, for the case uv cannot cover:
# a managed JupyterHub, a locked-down laptop, a CI image that already has an
# interpreter. The supported path is uv, which installs the exact versions
# pinned in uv.lock and fetches a matching Python by itself:
#
#     uv sync
#
# This file is not pinned, because pinning it here would be a second lockfile
# to keep in step with the first one, and there is no mechanism that would
# notice when it drifted.
#
#     python -m venv .venv && . .venv/bin/activate
#     pip install -r requirements.txt
#     pip install -e .              # for `import eln` and `import modelgraph`
#     marimo edit notebooks/00_build_document.py
#
# Python 3.12. pyenzyme needs at least 3.11, and the project pins 3.12 so that
# every install is the same one; a newer Python is where the wheels run out.
#
# Nothing here is optional and nothing is commented out. The four steps of the
# workshop are one thing to install, not four, and a participant discovering in
# step 2 that they installed the wrong subset costs the room more than these
# few megabytes.

# --- the converter itself -----------------------------------------------
rocrate>=0.15            # the reference RO-Crate implementation; builds the .eln

# --- the notebooks ------------------------------------------------------
marimo>=0.11
pyenzyme>=2.2            # the official EnzymeML v2 data model
matplotlib>=3.7          # without it, plot.png is silently omitted

# --- the live graph view in step 0 --------------------------------------
# anywidget carries the ~300 lines of ES module in modelgraph/static. That
# module imports nothing, so the graph keeps working on a conference wifi that
# has stopped working.
anywidget>=0.9

# --- talking to an eLabFTW instance (steps 2 and 3) ---------------------
elabapi-python>=5.6

# --- checking an .eln against foreign code ------------------------------
# The ELN Consortium's own test suite, behind test/conformance.py.
jsonschema>=4
roc-validator
